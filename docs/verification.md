## Test evidence

- Pure calculations: 30-day/+3-day numerical example, both planning modes, latest relevant upload, offset changes, partial progress, relative weights, individual overrides, ignored administrative material, empty and zero-weight workloads, missing dates, invalid intervals, completion, before-start/deadline/overdue boundaries, supported calendar bounds, leap dates, and both DST transitions.
- Imports: repeated source IDs, preserved progress/weights/manual overrides, renamed categories, missing metadata, first-match relevance rules, unknown defaults, strict protocol versions, nonce/request/response shapes, unsafe and malformed URLs, size limits, and backup references.
- Parsers: actual public KIT link observations plus explicitly synthetic modern/legacy authenticated-layout fixtures, nested-folder categories, breadcrumb course context, reliable upload labels, ambiguous references, login pages, sanitized URLs and duplicates.
- React: honest empty state, accessible course creation, persistence and locale switching.
- Supabase SDK boundary: the real SDK with a simulated HTTP transport exercises save/load RPC bodies, revision conflicts, and malformed responses. This is **not a hosted Supabase connection test**.
- Database: the actual production migration runs on PostgreSQL in PGlite with two authenticated identities and an anonymous role. It verifies private reads, inserts, updates, deletes, owner reassignment denial, composite foreign keys, revision conflicts, rollback after invalid data, source metadata, override fields and historical deleted-course references.
- Browser: creating a course and a custom category, renaming that category, adding material, changing partial/full completion, switching planning mode, reload persistence, dashboard, light/dark themes, mobile overflow, import approval, re-import idempotency and invalid-file handling.
- Extension runtime: Chromium loads the built extension, renders its popup, reads its manifest and storage, and exchanges a versioned import with the actual website; course data remains unchanged until approval. The bundled content script separately traverses same-origin mocked course/folder pages in the browser and reports access/login failure.
